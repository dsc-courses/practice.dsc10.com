Campuswire is an online discussion forum used by many college courses, including DSC 10. Students and instructional staff use it to ask questions, share announcements, and discuss course material.

The DataFrame posts has one row for every post made on a course’s Campuswire forum. The columns are:

  • "post_id" (int): A unique ID number for the post.
  • "title" (str): The title of the post.
  • "date" (str): The date the post was made, formatted as "YYYY-MM-DD", for example "2026-02-03".
  • "author_role" (str): The role of the author, either "student" or "staff".
  • "category" (str): The category the post was filed under, such as "General", "Quiz 1", "Projects", or "Homework 3".
  • "is_private" (bool): True if the post is visible only to the author and course staff, and False if it is visible to the whole class.
  • "is_question" (bool): True if the post is a question, and False if it is a note (such as an announcement or reminder).
  • "is_resolved" (bool): True if the post has been marked as resolved, and False otherwise.
  • "num_views" (int): The number of times the post has been viewed.
  • "num_likes" (int): The number of likes the post has received.
  • "num_comments" (int): The number of comments on the post.

Problem 3.2

(10 + five).sum()

Answer: 65

Here, the parentheses change the order of operations. 10 + five adds 10 to every element of the Series, giving a Series with values 14, 11, 16, 13, and 11. Summing these gives 65.

Equivalently, adding 10 to each of the 5 values increases the total by 10 * 5 = 50, so the result is 15 + 50 = 65. The only difference between this part and the previous one is when the 10 is added: once after summing, or to each element before summing.

Problem 3.3

((five + (five >= 5).sum()) >= 5).sum()

Answer: 2

It’s easiest to evaluate this expression from the inside out.

  1. five >= 5 is an element-wise comparison, giving a Boolean Series with values False, False, True, False, False.
  2. Calling .sum() on a Boolean Series counts the number of True values, since True is treated as 1 and False as 0. So (five >= 5).sum() evaluates to 1.
  3. five + 1 adds 1 to each element, giving a Series with values 5, 2, 7, 4, 2.
  4. Comparing this Series with >= 5 gives a Boolean Series with values True, False, True, False, False.
  5. Calling .sum() counts the True values, giving 2.

Problem 5.1

Which of the following evaluates to the title of the question with the third-highest number of views? Select all that apply.

  • posts.sort_values("num_views", ascending=False).get("title").iloc[2]

  • posts[posts.get("is_question") == True].get(["title", "num_views"]).set_index("title").sort_values("num_views", ascending=False).index[2]

  • posts[posts.get("is_question")].sort_values("num_views", ascending=False).get("title").loc[2]

  • posts[posts.get("is_question") == True].sort_values("num_views", ascending=False).get("title").iloc[2]

  • posts[posts.get("is_question")].sort_values("num_views", ascending=False).get("title").iloc[-3]

  • None of the above.

Answer: Option 2, 4

Option 1: posts.sort_values("num_views", ascending=False).get("title").iloc[2] This never filters to questions. It returns the title of the post with the third-highest views among all posts, which may not be a question.

Option 2: posts[posts.get("is_question") == True].get(["title", "num_views"]).set_index("title").sort_values("num_views", ascending=False).index[2] This keeps only the questions and the two needed columns, makes "title" the index, and sorts by views in descending order. .index[2] takes the third element of the index, which is the title of the third-most-viewed question. The titles are in the index, not a column, so .index is the right way to get to them.

Option 3: posts[posts.get("is_question")].sort_values("num_views", ascending=False).get("title").loc[2] The filter posts[posts.get("is_question")] is fine. "is_question" is already a Boolean column, so it works the same as == True. The problem is .loc[2]. .loc looks up the row with index label 2, and sorting rearranges rows without changing their labels. So this returns the title of whichever post was originally in row 2, not the post in third place after sorting. If row 2 isn’t a question, it was filtered out, and this raises a KeyError.

Option 4: posts[posts.get("is_question") == True].sort_values("num_views", ascending=False).get("title").iloc[2] This keeps only questions, sorts them from most to fewest views, and gets the titles. .iloc[2] takes the item at position 2, which is the third item. That is the third-most-viewed question.

Option 5: posts[posts.get("is_question")].sort_values("num_views", ascending=False).get("title").iloc[-3] The filtering and sorting are correct. However, .iloc[-3] counts from the end, so with a descending sort it gives the question with the third-lowest number of views.

Problem 5.2

Which of the following evaluates to the number of views of the post with "post_id" 104? Select all that apply.

  • posts.get("num_views").loc[3]

  • posts.get("num_views").iloc[3]

  • posts.set_index("post_id").get("num_views").loc[104]

  • posts.set_index("post_id").get("num_views").iloc[104]

  • posts.sort_values("num_views").get("num_views").iloc[3]

  • posts.sort_values("num_views").get("num_views").loc[3]

  • posts[posts.get("post_id") == 104].get("num_views").iloc[0]

  • None of the above.

Answer: Option 1, 2, 3, 6, 7

Option 1: posts.get("num_views").loc[3]   Post 104 is in the row with index label 3, so .loc[3] returns its number of views.

Option 2: posts.get("num_views").iloc[3]   posts has the default index, so label 3 and position 3 are the same row. .iloc[3] returns the same value as .loc[3].

Option 3: posts.set_index("post_id").get("num_views").loc[104]   After "post_id" becomes the index, the post IDs are the labels. .loc[104] looks up the label 104 directly. This is the most robust option, because it doesn’t depend on where the post sits in the table.

Option 4: posts.set_index("post_id").get("num_views").iloc[104]   .iloc uses positions, not labels. .iloc[104] asks for the 105th row, which either doesn’t exist (IndexError) or is a different post. Use .loc to look up by post ID.

Option 5: posts.sort_values("num_views").get("num_views").iloc[3]   After sorting, position 3 holds the post with the fourth-smallest number of views. That is not necessarily post 104.

Option 6: posts.sort_values("num_views").get("num_views").loc[3]   Sorting reorders the rows, but each row keeps its original index label. .loc[3] finds the row labeled 3, which is still post 104, wherever it ended up after sorting.

Option 7: posts[posts.get("post_id") == 104].get("num_views").iloc[0]   The query keeps only the row where "post_id" is 104, which gives a one-element Series. .iloc[0] pulls out that one value. Note that .loc[0] would not work here: the remaining row still has label 3, so there is no label 0.

Suppose the array assignments contains the names of all assignments in a course. For example, assignments[0] might be "Homework 1".

Suppose also that the array due_dates contains the deadlines for all assignments in the course, in the same order as in assignments. In particular, both arrays have the same length. The entries of due_dates are strings formatted like "YYYY-MM-DD". For example, due_dates[0] might be "2026-01-12".

Our goal in this problem is to create a string called reminders that contains sentences describing when each assignment is due, with one space after each sentence. For example, in a class with only three assignments, the output may look like this:

"Homework 1 is due on 2026-01-12. Homework 2 is due on 2026-01-17. Midterm Project is due on 2026-01-25. "

Complete the for-loop below so that reminders is a string formatted like the above example, using all the assignments and deadlines in assignments and due_dates.

reminders = __(a)__
for i in __(b)__:
    reminders = __(c)__

Answer:

  • (a): "" Our resulting string, reminders, must be initialized as an empty string because when appending sentences to the result, we should not be starting with any extra text.
  • (b): np.arange(len(assignments)) or np.arange(len(due_dates)) The number of iterations in the for loop is determined by the length of either the assignments or due_dates arrays, which will have the same length (per the instructions above). In order to loop through each assignment from the beginning, we create an array using the length of the array, which produces elements starting at index 0 and continues until length - 1, as np.arange(n) stops right before n, giving us exactly len number of elements.
  • (c): reminders + assignments[i] + " is due on " + due_dates[i] + ". " The first part of this statement (reminders) helps us reassign the existing reminders string to the reminders variable, allowing us to append whatever comes after to it. The second part (assignments[i]) allows us to return the corresponding assignment name to the iteration we’re on, based on the assignments array. The third part (” is due on “) must have a space before is and after on in order to be correctly spaced when adjoined to the second and fourth parts. The fourth part (due_dates[i]) allows us to return the corresponding due date to the iteration we’re on, based on the due_dates array. Finally, the last part (”. “) finishes off the sentence with a period and a space that is there to make sure the next sentences that get appended aren’t starting immediately after the period.

Problem 10.1

How many private questions took at least 40 minutes to receive a response? Give your answer as an integer.

Answer: 50

In a density histogram, the area of a bar (width × height) is the proportion of values in that bin. In the private histogram, the bins at or above 40 minutes are [40, 80) and [80, 160]. Their areas are 40(0.00675) = 0.27 and 80(0.002875) = 0.23, so 0.27 + 0.23 = 0.5 of the 100 private questions took at least 40 minutes. That’s 100(0.5) = 50 questions.

Equivalently, the bars below 40 minutes have total area 20(0.015) + 20(0.01) = 0.5, so 1 - 0.5 = 0.5 of the questions took at least 40 minutes.

Problem 10.3

Suppose we make a single density histogram for all 400 questions, with one bin being [20, 40). What would the height of this bar be?

  • \dfrac{1}{80} = 0.0125

  • \dfrac{11}{800} = 0.01375

  • \dfrac{3}{200} = 0.015

  • \dfrac{1}{40} = 0.025

  • \dfrac{11}{40} = 0.275

  • Not enough information.

Answer: \dfrac{11}{800} = 0.01375

Both histograms have a [20, 40) bin. That bin holds 20(0.015)(300) = 90 public questions and 20(0.01)(100) = 20 private questions, so 110 of the 400 questions fall in [20, 40). In a density histogram, the height of a bar is the proportion of values in the bin divided by the bin width, so the height is \dfrac{110/400}{20} = \dfrac{11}{800} = 0.01375.
