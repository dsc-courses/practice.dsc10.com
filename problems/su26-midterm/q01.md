# BEGIN SUBPROB

Complete the implementation of the function `minutes` which takes as
input a single duration as a string and returns that duration in
minutes, as an `int`. Example inputs and outputs are given below.

    >>> minutes("22m")
    22

    >>> minutes("4m 45s")   # seconds do not contribute to the output
    4

    >>> minutes("1h 31m 2s")
    91

Fill in blanks (i), (ii), and (iii).

    def minutes(d):
        total = 0
        parts = __(i)__
        for part in parts:
            if part[-1] == "h":
                total = __(ii)__
            if part[-1] == "m":
                total = __(iii)__
        return total

# BEGIN SOLUTION

**Answer (i):** `d.split(" ")`

**Answer (ii):** `total + int(part.strip("h")) * 60`

**Answer (iii):** `total + int(part.strip("m"))`

The pieces of a duration are separated by spaces, so `d.split(" ")`
breaks the string into a list with one element per piece. For example,
`"1h 31m 2s"` becomes `["1h", "31m", "2s"]`.

The `for` loop then looks at the last character of each piece to decide
what unit it is measured in.

- **Blank (ii):** If the piece ends in `"h"`, it's a number of hours.
  Strip off the `"h"`, convert what's left to an `int`, and multiply by
  $60$ to convert hours to minutes. Add that to the running total.
- **Blank (iii):** If the piece ends in `"m"`, it's already a number of
  minutes, so just strip the `"m"`, convert to an `int`, and add it to
  the running total.

Notice there is no `if` statement for pieces ending in `"s"`. That's
intentional: seconds do not contribute to the output, so those pieces
are simply ignored.

Tracing through `minutes("1h 31m 2s")`: the piece `"1h"` contributes
$1 \cdot 60 = 60$, the piece `"31m"` contributes $31$, and the piece
`"2s"` contributes nothing, for a total of $91$.

Complete the line of code to replace the `"duration"` column in the
`ufo` DataFrame so that `ufo.get(["duration"])` results in the DataFrame

    ufo = ufo.assign(__(i)__)

# BEGIN SOLUTION

**Answer (i):** `duration=ufo.get("duration").apply(minutes)`

Assigning to a column name that already exists **replaces** that column,
which is what we want here.

`ufo.get("duration")` is a Series of duration strings. Calling
`.apply(minutes)` on that Series runs the `minutes` function on every
element and returns a new Series of the corresponding integers. Note
that we pass `minutes` without parentheses — we want to hand `.apply`
the function itself, not call it.

Since the new column is named `duration`, we write it as the keyword
argument `duration=...` inside `.assign`.

**For the rest of the exam, we'll assume that `ufo` contains the updated
`"duration"` column.**

The following four expressions are each intended to find the duration of
the longest sighting in minutes. **Select all that are correct.**

[ ] `ufo.take(np.arange(5)).get("duration").iloc[0]`
[ ] `ufo.get("duration").max()`
[ ] `ufo.sort_values("duration").get("duration").iloc[-1]`
[ ] `ufo.sort_values("duration", ascending=False).get("duration").loc[0]`

# BEGIN SOLUTION

**Answer:** Options 2 and 3.

- **Option 1:** `ufo.take(np.arange(5))` keeps only the first five rows,
  and `.iloc[0]` then grabs the duration of the very first row. There's
  no reason the first row would hold the largest duration, so this is
  incorrect.
- **Option 2:** `.max()` on the `"duration"` Series returns the largest
  duration directly. Correct.
- **Option 3:** `.sort_values("duration")` sorts in **ascending** order
  by default, so the largest duration ends up in the last position, and
  `.iloc[-1]` retrieves it. Correct.
- **Option 4:** Sorting in descending order does put the largest
  duration in the first *position*, but `.loc[0]` looks up the element
  with **index label** `0`, not the element in position `0`. Sorting
  rearranges the rows but carries the original index labels along, so
  `.loc[0]` still returns the duration of the row that was originally
  row `0`. To make this work we'd need `.iloc[0]` instead.
