# BEGIN PROB

The course tutors are constantly competing to give the best, most thoughtful answers on Campuswire. To determine who is the nicest tutor, the course staff run a weekly **Kindness Check**: they select **4 posts at random, without replacement**, from `posts` and read every tutor reply on them. Since only questions receive replies, Jeffrey is hoping that the Kindness Check lands on more questions than notes. That way, he has more chances to show everyone just how nice he can be.

Fill in the blanks below so that `prob_more_questions` is an estimate of the probability that a Kindness Check contains **more questions than notes**.

```py
repetitions = 10000
count = 0
for i in np.arange(repetitions):
    check = np.random.choice(__(a)__)
    if __(b)__:
        count = count + 1
prob_more_questions = count / repetitions
```

# BEGIN SOLUTION

**Answer:** `posts.get("is_question"), 4, replace=False`

Explanation: The Kindness Check randomly selects $4$ posts without replacement, and we want to determine whether more of these posts are questions than notes. We use `posts.get("is_question")` because this column contains Boolean values indicating whether each post is a question (True) or a note (False). These values provide exactly the information needed for the simulation. We specify $4$ because each Kindness Check contains four posts, and replace=False because the posts are selected without replacement, meaning the same post cannot be selected more than once within a single check. Using replace=True would allow repeated selections, which does not match the question. Selecting from np.array([True, False]) would also be inappropriate because it would not preserve the actual proportions of questions and notes in the DataFrame.

# BEGIN SOLUTION

**Answer:**

- `np.count_nonzero(check) >= 3`
- `check.sum() > (4 - (check).sum())`
- `check.mean() > 0.5`

Explanation: Since each Kindness Check contains $4$ posts, having more questions than notes means at least $3$ of the $4$ selected posts must be questions. The "is_question" column contains Boolean values, where True represents a question and False represents a note. In numerical operations, True behaves like $1$ and False behaves like $0$.

The expression `np.count_nonzero(check) >= 3` is correct because `np.count_nonzero(check)` counts the number of True values. Requiring at least $3$ ensures that questions outnumber notes.

The expression `check.sum() > (4 - check.sum())` is also correct because `check.sum()` counts the questions, while `4 - check.sum()` counts the notes. Comparing these values directly checks whether there are more questions than notes.

Finally, `check.mean() > 0.5` is correct because the mean of a Boolean array represents the proportion of True values. A mean greater than $0.5$ means more than half of the selected posts are questions.

The other expressions are incorrect. `np.count_nonzero(check) >= 2` allows exactly $2$ questions and $2$ notes, which is a tie rather than more questions. Similarly, `np.count_nonzero(check) > 0.5` is satisfied whenever there is at least one question, which does not guarantee that questions outnumber notes.

Jeffrey copies the correct simulation into his own notebook, but in his excitement, he accidentally moves the line `count = 0` to the inside of the `for`-loop:

```py
repetitions = 10000
for i in np.arange(repetitions):
    count = 0
    check = np.random.choice(__(a)__)
    if __(b)__:
        count = count + 1
prob_more_questions = count / repetitions
```

Assuming that blanks (a) and (b) are filled in correctly, which of the following **could** `prob_more_questions` evaluate to after Jeffrey's code finishes running? **Select all that apply.**

[ ] `0.0`
[ ] `0.0001`
[ ] `0.5`
[ ] `1.0`
[ ] None of the above.

# BEGIN SOLUTION

**Answer:**

- `0.0`
- `0.0001`

Explanation: In the original simulation, `count = 0` is placed before the for loop so that the counter keeps track of how many successful Kindness Checks occur across all $10,000$ repetitions. However, Jeffrey moves `count = 0` inside the loop, causing the counter to reset to zero at the beginning of every repetition. As a result, the successes from previous repetitions are lost.

During each repetition, the counter starts at $0$ and can increase to $1$ if the selected check contains more questions than notes. Therefore, after the final repetition, count can only be either $0$ or $1$, depending on whether the last check satisfies the condition.

Since `prob_more_questions = count / repetitions` and `repetitions = 10000`, the only possible results are $0 / 10000 = 0.0$ and $1 / 10000 = 0.0001$.

Values such as $0.5$ and $1.0$ are impossible because they would require count to be much greater than $1$. The counter never accumulates successes across repetitions because it is reset each time.
