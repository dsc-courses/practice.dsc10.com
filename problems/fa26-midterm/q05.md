# BEGIN SUBPROB

Which of the following evaluates to the title of the **question** with the third-highest number of views? **Select all that apply.**

[ ] `posts.sort_values("num_views", ascending=False).get("title").iloc[2]`
[ ] `posts[posts.get("is_question") == True].get(["title", "num_views"]).set_index("title").sort_values("num_views", ascending=False).index[2]`
[ ] `posts[posts.get("is_question")].sort_values("num_views", ascending=False).get("title").loc[2]`
[ ] `posts[posts.get("is_question") == True].sort_values("num_views", ascending=False).get("title").iloc[2]`
[ ] `posts[posts.get("is_question")].sort_values("num_views", ascending=False).get("title").iloc[-3]`
[ ] None of the above.

# BEGIN SOLUTION

**Answer:** Option 2, 4

Option 1:
`posts.sort_values("num_views", ascending=False).get("title").iloc[2]` This never filters to questions. It returns the title of the post with the third-highest views among *all* posts, which may not be a question. 

Option 2:
`posts[posts.get("is_question") == True].get(["title", "num_views"]).set_index("title").sort_values("num_views", ascending=False).index[2]` This keeps only the questions and the two needed columns, makes `"title"` the index, and sorts by views in descending order. `.index[2]` takes the third element of the index, which is the title of the third-most-viewed question. The titles are in the index, not a column, so `.index` is the right way to get to them. 

Option 3:
`posts[posts.get("is_question")].sort_values("num_views", ascending=False).get("title").loc[2]` The filter `posts[posts.get("is_question")]` is fine. `"is_question"` is already a Boolean column, so it works the same as `== True`. The problem is `.loc[2]`. `.loc` looks up the row with index *label* 2, and sorting rearranges rows without changing their labels. So this returns the title of whichever post was originally in row 2, not the post in third place after sorting. If row 2 isn't a question, it was filtered out, and this raises a `KeyError`. 

Option 4:
`posts[posts.get("is_question") == True].sort_values("num_views", ascending=False).get("title").iloc[2]` This keeps only questions, sorts them from most to fewest views, and gets the titles. `.iloc[2]` takes the item at *position* 2, which is the third item. That is the third-most-viewed question. 

Option 5:
`posts[posts.get("is_question")].sort_values("num_views", ascending=False).get("title").iloc[-3]` The filtering and sorting are correct. However, `.iloc[-3]` counts from the end, so with a descending sort it gives the question with the third-*lowest* number of views.

# BEGIN SUBPROB

Which of the following evaluates to the number of views of the post with `"post_id"` `104`? **Select all that apply.**

[ ] `posts.get("num_views").loc[3]`
[ ] `posts.get("num_views").iloc[3]`
[ ] `posts.set_index("post_id").get("num_views").loc[104]`
[ ] `posts.set_index("post_id").get("num_views").iloc[104]`
[ ] `posts.sort_values("num_views").get("num_views").iloc[3]`
[ ] `posts.sort_values("num_views").get("num_views").loc[3]`
[ ] `posts[posts.get("post_id") == 104].get("num_views").iloc[0]`
[ ] None of the above.

# BEGIN SOLUTION

**Answer:** Option 1, 2, 3, 6, 7

Option 1:
`posts.get("num_views").loc[3]`
  Post `104` is in the row with index label 3, so `.loc[3]` returns its number of views.

Option 2:
`posts.get("num_views").iloc[3]`
  `posts` has the default index, so label 3 and position 3 are the same row. `.iloc[3]` returns the same value as `.loc[3]`.

Option 3:
`posts.set_index("post_id").get("num_views").loc[104]`
  After `"post_id"` becomes the index, the post IDs are the labels. `.loc[104]` looks up the label `104` directly. This is the most robust option, because it doesn't depend on where the post sits in the table.

Option 4:
`posts.set_index("post_id").get("num_views").iloc[104]`
  `.iloc` uses positions, not labels. `.iloc[104]` asks for the 105th row, which either doesn't exist (`IndexError`) or is a different post. Use `.loc` to look up by post ID.

Option 5:
`posts.sort_values("num_views").get("num_views").iloc[3]`
  After sorting, position 3 holds the post with the fourth-smallest number of views. That is not necessarily post `104`.

Option 6:
`posts.sort_values("num_views").get("num_views").loc[3]`
  Sorting reorders the rows, but each row keeps its original index label. `.loc[3]` finds the row labeled 3, which is still post `104`, wherever it ended up after sorting.

Option 7:
 `posts[posts.get("post_id") == 104].get("num_views").iloc[0]`
  The query keeps only the row where `"post_id"` is `104`, which gives a one-element Series. `.iloc[0]` pulls out that one value. Note that `.loc[0]` would *not* work here: the remaining row still has label 3, so there is no label 0.
