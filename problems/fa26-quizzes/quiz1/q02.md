# BEGIN PROB

After a few months of operation, Coleman notices that there are a few bugs in his restaurant data dashboard. For each expression below, help Coleman figure out what the expression will evaluate to, or write "error" if the expression produces an error.

# BEGIN SUBPROB

```py
menu.take(np.arange(3, 0, -1)).shape[1]
```

# BEGIN SOLUTION

**Answer:** `4`

np.arange(3, 0, -1) decrements by 1 from 3 and stops before 0, producing [3, 2, 1]. take() grabs rows at those positions, so we get a DataFrame with 3 rows. .shape on its own is (rows, columns), so .shape[1] is the number of columns. "Name" is the index, so it doesn’t count. The columns are "Type", "Price", "Pieces", and "Rating", which means .shape[1] called on the previosu part of the expression evaluates 4. The row order doesn’t matter here.

# BEGIN SUBPROB

```py
np.array([10, menu.get("Type").loc["Tuna Sashimi"], 1.5])[2]
```

# BEGIN SOLUTION

**Answer:** `"1.5"`

Looking at the second element of this array, menu.get("Type") produces a series with just the "Type" column and the names being the index; .loc["Tuna Sashimi"] produces the value of "Type" at the row labeled "Tuna Sashimi", which is "Sashimi" (a string). Because a NumPy array can only hold one data type, when you mix an int (first element, 10), a string (second element, "Sashimi"), and a float (third element, 1.5), NumPy converts everything to the most flexible data type, which is a string in this case. The array is ["10", "Sashimi", "1.5"]. This array at index 2 is "1.5", and since it’s a string, it needs quotes.

# BEGIN SUBPROB

```py
int(str(menu.get("Rating").max()))
```

# BEGIN SOLUTION

**Answer:** error
The menu.get("Rating").max() part of the expression returns a float, like 5.0. str(5.0) is "5.0". int() on a string only works if the string looks like a whole number, like "5". "5.0" contains a decimal point, so Python raises a ValueError.
